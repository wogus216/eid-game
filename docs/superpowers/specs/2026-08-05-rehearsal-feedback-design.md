# 리허설 피드백 반영 설계 — 함성 수동 시작 · 선물 2라운드

작성일: 2026-08-05
대상: `eid-game` (건양대 AI·SW 캠프 데시벨 게임)

## 배경

리허설에서 두 가지 피드백이 나왔다.

1. **시도 화면에 들어가는 순간 게이지가 저절로 차오른다.** 관객이 숨을 고르기도 전에 3.2초 연출이 끝나 함성 타이밍과 어긋난다. 1·2·3차 전부 같은 문제.
2. **돌림판 당첨 보드가 4칸인데 선물은 1차 3개, 2차 3개다.** 총 6명을 3명씩 두 번 뽑아야 한다.

현재 코드에서 각각 `DecibelScene.tsx`의 `Attempt` 마운트 시점 자동 재생, `config.ts`의 `winnerCount: 4`에서 비롯된다.

## A. 데시벨 — 시도마다 "준비 → 함성" 2단계

### 상태 모델

`decibel` 씬의 `step`을 시도당 두 칸으로 늘린다.

| step | 의미 |
|---|---|
| 0 | 인트로 |
| 1, 3, 5 | k차 **준비** (k = ⌈step/2⌉) |
| 2, 4, 6 | k차 **함성** |

`DECIBEL_LAST_STEP`은 `CONFIG.attempts.length` → `CONFIG.attempts.length * 2`가 된다. `step`에서 시도 인덱스와 단계를 뽑는 순수 함수를 `showMachine.ts`에 둔다.

```
attemptIndexOf(step) = Math.ceil(step / 2) - 1
isRunningStep(step)  = step > 0 && step % 2 === 0
```

`reduce`의 `NEXT`/`BACK` 분기는 지금 그대로 `step ± 1`이면 되므로 상태기계 로직 자체는 바뀌지 않는다. 바뀌는 건 마지막 step 값과 화면 해석뿐이다.

### 화면 동작

**준비 단계** — 게이지는 바닥에서 ±1.5dB 폭으로만 미세하게 떨린다. 절대 상승하지 않는다. 꾸미는 해당 시도의 `say` 대사를 띄운 채 `tense` 표정으로 대기한다. 긴장 연출(`setTension`)은 이 시점부터 걸어 시도가 거듭될수록 세계가 조여드는 감각을 유지한다. 함성 지속음(`sfx.riseStart`)은 아직 울리지 않는다. `setBusy(false)`이므로 운영자에게 큐 칩 `▶ k차 함성 시작!`이 보인다.

**함성 단계** — Enter를 누른 순간부터 기존 3.2초 상승·지터·판정 연출을 그대로 재생한다. `sfx.riseStart`, `setShout`, 성공 시 `breakthrough`/`quake`/`flash`까지 현재 로직을 유지한다. 진행 중 `setBusy(true)`, 끝나면 `false`로 풀고 `done` 대사로 전환한다.

**되돌리기** — ←(BACK)로 준비 단계에 돌아가면 같은 시도를 다시 재생할 수 있다. 리허설·사고 복구용으로 유용하며, 별도 구현 없이 step 감소만으로 성립한다.

### `useDecibelAnim` 변경

`running: boolean` 인자를 추가한다. `running === false`면 키프레임 보간을 돌리지 않고 0dB 기준의 미세 지터 값만 반환한다. `running === true`가 되는 시점을 애니메이션 시작 기준(`performance.now()`)으로 삼는다. 키프레임·지속 시간·판정 콜백은 손대지 않는다.

### 큐 문구

`CONFIG.copy.cue`에 준비/시작을 구분하는 문구를 둔다.

- 인트로에서 Enter → `1차 준비`
- 준비 단계에서 Enter → `1차 함성 시작!`
- 함성이 끝난 뒤 Enter → `2차 준비` (마지막 시도 뒤에는 `돌림판으로`)

## B. 돌림판 — 3칸 × 2라운드

### 설정

`winnerCount: 4`를 없애고 라운드 목록으로 대체한다.

```ts
prizeRounds: [
  { label: '1차 선물', count: 3 },
  { label: '2차 선물', count: 3 },
]
```

총 당첨 인원(6)은 `prizeRounds`의 합으로 파생한다. 이 값은 입장 인원 하한(`ADJUST_ENTRY`의 `Math.max`)에도 쓰인다.

### 진행 규칙

`roulette` 씬의 `step`은 **현재 라운드 인덱스**(0, 1)를 뜻한다. `NEXT`는 다음 순서로 판정한다.

1. 현재 라운드 정원이 안 찼으면 → 한 명 추첨 (`winners`, `drawnHistory`에 누적)
2. 정원이 찼고 다음 라운드가 있으면 → `step + 1`. 보드를 비우고 2차로 전환하며, **추첨은 하지 않는다**
3. 마지막 라운드까지 찼으면 → `result`로 이동

2번이 핵심이다. 1차 3명을 발표한 뒤 화면이 멈춰 대기하므로 그 사이에 1차 선물을 나눠줄 수 있다. 큐 칩은 `▶ 2차 선물 추첨`.

`winners`는 지금처럼 단일 누적 배열로 두고, 라운드 경계는 `prizeRounds`의 누적합으로 계산한다. `drawnHistory`가 이미 중복을 막으므로 1차 당첨자가 2차에 다시 나오지 않는다.

`lastStepOf('roulette')`는 `prizeRounds.length - 1`이 되어 BACK으로 씬을 거슬러 올라갈 때 라운드 위치가 보존된다.

### 화면

- 당첨 보드는 **항상 3칸**이며 현재 라운드에서 뽑힌 번호만 보여준다.
- 돌림판 위에 현재 라운드 라벨(`1차 선물` / `2차 선물`)을 표시한다. 경품명은 넣지 않는다 — 막판에 경품이 바뀌어도 코드를 건드릴 필요가 없게 한다.

### 재추첨 버튼

R키만으로 되던 재추첨을 화면 버튼으로 노출한다. 사회자가 단축키를 외우지 않아도 되게 하는 것이 목적이다.

- **위치·모양**: 화면 우하단에 작은 칩 버튼. 좌하단 큐 칩(`Enter ▶ …`)과 같은 눈높이·톤으로 만들어 운영 UI가 한 계열로 읽히게 한다. 문구는 `다시 뽑기`.
- **표시 조건**: `roulette` 씬에서 현재 라운드에 뽑힌 번호가 있고, 스핀이 끝나 번호가 공개된 상태(`busy === false`)일 때만 보인다. 스핀 중과 라운드 전환 직후에는 숨긴다.
- **동작**: 한 번 클릭하면 즉시 `REDRAW_LAST`. 확인 절차는 두지 않는다 — 무대에서 멈칫하는 시간이 더 나쁘다.
- **R키는 백업으로 유지**한다.
- `REDRAW_LAST`는 현재 라운드에서 뽑힌 게 있을 때만 동작한다. 라운드 전환 직후에는 이전 라운드 당첨자를 지우지 않는다.

구현 시 함정 두 가지:

1. `App.tsx`의 window `pointerdown` 핸들러가 터치 탭을 `NEXT`로 해석한다. 버튼에서 `stopPropagation`을 하지 않으면 터치 조작 시 재추첨과 다음 추첨이 함께 발동한다.
2. 클릭 후 포커스가 버튼에 남으면 이어지는 Enter 키가 진행이 아니라 버튼을 다시 누른다. 클릭 직후 `blur()`로 포커스를 놓는다.

### 결과 화면

카드 6장을 `1차 선물` / `2차 선물` 두 그룹으로 나눠 표시한다. 순번 배지는 라운드 안에서 1~3으로 매긴다.

현재 레이아웃은 카드 4장 기준이라 6장이면 좁아진다. 카드 크기와 줄 간격을 조정하되, 정확한 값은 1920×1080 무대 화면에서 실제로 띄워보고 정한다.

### 저장 데이터

localStorage 키를 `eid-decibel-game-v1` → `-v2`로 올린다. 리허설 중 저장된 4명 기준 상태가 새 구조로 복구되는 것을 막는다. `load()`의 형태 검증은 그대로 둔다.

## 테스트

`showMachine.test.ts`를 새 구조에 맞춰 갱신한다.

- 인트로 → 3차 함성까지 Enter 6번으로 도달하고, 7번째에 돌림판으로 넘어간다
- 준비 step과 함성 step이 `attemptIndexOf`/`isRunningStep`으로 올바르게 해석된다
- BACK으로 함성 → 준비로 되돌아간다
- 돌림판에서 Enter 3번에 1차 3명이 차고, 4번째는 **추첨 없이** 라운드만 전환한다
- 5~7번째에 2차 3명이 차고, 8번째에 결과로 간다
- 6명 전원이 서로 다른 번호다 (라운드 간 중복 없음)
- 입장 인원을 6명 미만으로 내릴 수 없다
- `REDRAW_LAST`가 현재 라운드의 마지막 당첨자만 교체하고, 라운드 전환 직후에는 아무것도 바꾸지 않는다

`draw.test.ts`, `persistence.test.ts`는 변경 대상이 아니다.
